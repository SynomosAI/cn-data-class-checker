# cn-data-class-checker

> **状态：RESERVED（占位 · 开放认领）** — 本仓已按平台协议规范建好行业接入四件套骨架，
> 等待具备本域资质的运营方认领并填充真实规则。

把「这份数据属于哪一类哪一级、对应什么保护义务」拆成可核验的属性，让 AI 只做提示，不做终局定级。

## 这个域管什么

数据分类分级与保护义务判定（GB/T 43697 中国口径）

数据分类分级是个人信息保护与数据安全合规的地基。一般数据、重要数据、核心数据的识别直接决定保护强度与出境要求。AI 能做的是把要素摆清楚，定级须由数据责任方确认。

## 属性清单

| 属性键 | 类型 | 说明 |
|---|---|---|
| `dat.data_class` | enum | 按 GB/T 43697-2024 数据安全技术 数据分类分级规则 · 取值 general/important/core/undetermined |
| `dat.sensitivity` | enum | 敏感度，用于访问控制与展示策略 · 取值 public/internal/confidential/secret |
| `dat.contains_personal_info` | boolean | 是否含个人信息，含则叠加个人信息保护义务 |
| `dat.cross_border_obligation` | enum | 出境路径义务，须人工确认 · 取值 none/contract_required/security_assessment/certification/prohibited |
| `dat.retention_policy` | string | 留存期限与到期处置方式 |

## 本域红线（不可逾越，机器可读）

1. 重要数据与核心数据的识别须经数据责任方人工确认，AI 不得自行定级
2. 不得输出「已满足出境条件」类结论，出境须走法定路径
3. 不下数据定级终局结论，仅输出要素核查与义务提示

> 红线在 `gate-map.json` 中均有对应阻断规则。平台校验器会检查「每条红线都有规则覆盖」，
> 缺失即校验失败——**制度与系统不允许不同步**。

## 行业接入四件套

| 文件 | 作用 |
|---|---|
| `domain.manifest.json` | 本域声明：属性清单、签发方要求、有效期、红线 |
| `gate-map.json` | 本域「什么动作要多少摩擦」：silent / warn / confirm / block / require-owner |
| `privacy.json` | 本域隐私声明：默认关闭、最小必要、可撤回、可删除 |
| `checker` | 本域核验器（MCP 工具，**只出示核验，不下判定**） |

## 核心原则

**平台只当擂台，不当货架。** 本域的核验器只回答「这条声明是否可核验、缺什么要件」，
不回答「这件事是否合规、该不该做」。判定权在本域的资质方、监管方与人。

**隐私是准入条件，不是整改事项。** 缺失 `privacy.json` 或任一必填字段不符，
符合性校验直接失败——不是警告，是拒绝接入。
